# 会话重放与压力测试

> 抓到的请求不只是能看——还能**再跑一遍**。本篇教你两种玩法：**会话重放**把一串请求按原顺序**成批复现**（复现流程、回归验证、换环境重放）；**压力测试**对某一条请求**高频施压**，实时看它的吞吐与延迟分位。两者都能从抓包列表**右键直达**，签名 / 时间戳类私有接口也照跑不误，不用手动重填参数。

---

## 一、什么时候用

按你的目的挑一种：

- 想把一个**多步流程**或**时序相关**的问题**原样复现**、或**批量回归**一组接口 → 用 **会话重放**（下面场景 A）。
- 想把线上抓到的一段请求**切到测试环境**再跑一遍 → 用 **会话重放**（场景 A，配环境切换）。
- 抓到某个接口，想知道它**扛不扛得住**、在某个 QPS 下**真实延迟**是多少 → 用 **压力测试**（场景 B）。

如果你只是想改改**单条**请求再发一次，用 [请求构造与重放](17-请求构造与重放.md) 更趁手；本篇专攻「多条按序」和「单条高频」两件事。

---

## 二、前置条件

- 已安装并启动 TraceEagle。
- **已经抓到了要复用的请求**（任意一种抓法都行，见 [快速开始](01-快速开始.md)）；没有现成抓包也可以在面板里手动新增请求。
- 想切环境重放的话，先准备好目标环境的地址；签名 / 时间戳类接口无需手算，面板支持动态值自动生成。

---

## 三、分步操作

### 场景 A：会话重放——一串请求成批按序重放

1. **选中要重放的请求。** 在抓包列表里勾选多条，右键 **「重放选中的请求」**；只想放一条也可以右键 **「重放此请求」**。方法 / URL / 头 / Body 会自动带入。
2. **（可选）补充或微调。** 在面板里点 **「+ 新增请求」** 手动加请求；每一条都能就地编辑方法 / URL / 参数 / 头 / Body，顺序即执行顺序。
3. **（可选）设循环与间隔。**
   - **循环次数**：整串序列重复跑 N 次。
   - **请求间隔**：每条之间暂停一段时间，还原真实节奏。
4. **（可选）切换环境。** 选一个目标环境，一键把整串请求切过去重放——线上抓的、测试环境跑。
5. **点开始，成批按序发出。** 工具按你排好的顺序逐条发送。

![会话重放：把选中的多条请求按抓包顺序成批重放，可设循环与间隔，逐条给出状态码与延迟、总体成功 / 失败计数](../introduce/img/06-session-replay.png)

### 场景 B：压力测试——对单条右键「压测此请求」

1. **挑一条要施压的请求，右键 「压测此请求」。** 方法 / 地址 / 头 / 体自动带入并**立即开始**，缺失的协议自动补全。
   - 也可以从工具箱打开 **「压测」** 手动配置目标与参数；它是浮窗形式，**可同时开多个窗口跑多个独立压测**，互不干扰。
2. **选压测模式。**
   - **恒定速率（QPS）**：按设定的每秒请求数均匀发压，采用更严谨的延迟统计口径，高负载下 **p99 等尾延迟依然真实、不虚低**——适合评估「这个接口在 X QPS 下的真实延迟」。
   - **并发**：固定并发数背靠背连发，用来**打最大吞吐**——适合测「极限能扛多少」。
3. **设压力参数。**
   - **速率**：每秒请求数（1–100000 req/s，恒定速率模式）。
   - **并发 / 连接数**：1–2000（并发模式）。
   - **持续时长**：1–3600 秒，按时长跑而非固定总数。
4. **（可选）调请求与高级项。** 方法、URL（可省协议，自动补 https）、Query 参数、请求头、请求体（JSON / 表单 / 原始）都能改；高级项支持**跟随重定向**、**跳过 TLS 校验**。
5. **开始施压，盯实时指标。** 随时可停；关闭窗口会自动停止在途压测。

![压力测试：大号实时 RPS + 吞吐折线，已发送 / 成功 / 错误 / 用时，p50–p99.9 与最大延迟分位，状态码分布](../introduce/img/06-load-test.png)

> 签名 / 时间戳才放行的私有接口，一样能成批重放、能压测——请求编辑支持环境变量与动态值（UUID、时间戳、随机数、Base64、MD5 / SHA、HMAC 签名、URL 编码等），不用手动算签名。写法见 [请求构造与重放](17-请求构造与重放.md)。

## 四、验证：确认跑起来了

**会话重放**——看结果面板逐条列出：

- 每条的**方法、URL、状态码、延迟**都在。
- 总览给出**总进度、成功 / 失败计数、总耗时**。状态码符合预期即复现成功。

**压力测试**——看实时结果区：

- **吞吐**：大号实时 RPS 数字 + 实时吞吐折线图在动。
- **计数**：已发送 / 成功 / 错误 / 已用时持续更新。
- **延迟分位**（毫秒）：p50 / p90 / p95 / p99 / p99.9 / 最大都有读数。
- **状态码分布**：2xx / 3xx / 4xx / 5xx / 错误 的彩色标签比例合理。

## 五、跑不动 / 结果不对？逐条排查

| 现象 | 多半是 | 怎么办 |
| --- | --- | --- |
| 重放 / 压测都是 4xx，抓时明明是 2xx | 接口要签名 / 时间戳，直接重发时旧值已过期 | 用动态值让签名 / 时间戳每次自动重算，见 [请求构造与重放](17-请求构造与重放.md) |
| 切了环境重放，请求发去了原地址 | 环境没选中或地址里写死了域名 | 确认已选目标环境；把写死的地址换成环境变量 |
| 压测状态码大量 4xx / 5xx，但不是目标接口本身的问题 | 目标做了跳转、或证书 / TLS 校验拦下 | 高级项打开**跟随重定向**；自签 / 测试证书打开**跳过 TLS 校验** |
| 压测 RPS 上不去 | 恒定速率模式的速率设太低，或并发数太小 | 恒定速率模式调高速率；要打极限改用**并发**模式并调大并发数 |
| 想同时压多个接口，开一个就占满了 | 只开了单个压测窗口 | 手动打开多个压测浮窗，各自独立跑，互不干扰 |
| 重放的请求列表里少了几条 | 右键时没有勾选、只带入了当前一条 | 先在列表勾选多条，再右键「重放选中的请求」；或在面板「+ 新增请求」补齐 |
