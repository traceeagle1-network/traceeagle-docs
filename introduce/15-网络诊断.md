# 网络诊断

> 网突然不好使了，是网卡、路由器、宽带、DNS，还是代理出了问题、或者被劫持到了登录页？与其一个个手动试，不如用这套诊断工具一站式排查：**一键分层自检**直接告诉你卡在哪一层，还能盯**连通性**、查 **DNS 有没有泄漏**。

---

## 一、一键分层自检：直接定位到「哪一层」

打开即自动开跑，从本机网卡一路查到网页访问，**逐层检查、实时出结果**，每步都带状态（通过 / 警告 / 失败）：

1. **本机网卡**：有没有可用的网卡和 IP。
2. **默认网关**：到路由器 / 局域网这一跳通不通——分清是「本地 / 路由器」还是「宽带 / 上游」的问题。
3. **公网连通**：不经 DNS、直接按 IP 探公网通不通（ICMP 被拦也能测）。
4. **DNS 解析**：域名能不能正常解析成 IP，解析多快。
5. **代理设置**：本机代理配置是否正常（见下方亮点）。
6. **网页访问**：能正常打开网页，还是被拦截 / 撞上需要登录的**认证门户**（连了 Wi-Fi 却要先登录那种）。

跑完给一句**结论 + 修复建议**，直接点明是「网卡 / 路由器 / 宽带 / DNS / 代理 / 认证门户」哪一环——**不用你逐层猜**。随时可「重新检测」。

## 二、亮点：自动揪出并清除「残留代理」

这是抓包 / VPN 用户最容易踩、又最难自查的坑：工具改过系统代理后异常退出，留下一个**指向已关闭端口的残留代理**，导致应用集体断网，却怎么都查不出原因。

网络诊断会**自动识别并清除**这类残留代理（本机与系统 / 浏览器两头一起清），并提示「已恢复」；正在正常使用中的代理只报告、不乱动。

> 「抓包一停就断网」时，这一步就是最快的自救。别的诊断工具通常只会告诉你「连不上」，不会帮你把根因清掉。

---

## 三、连通性探测：某台主机通不通、延迟多少

想盯住一条链路、或确认某台主机的可达性，用连通性探测：持续发探测、实时画延迟曲线。

- **两种探测方式**：**ICMP ping**（传统 ping）；**TCP ping**——向指定端口（如 443）探测，**ICMP 被防火墙拦时照样测出「端口级」可达性**。
- **实时统计**：发送 / 接收 / 丢包率，最近 / 平均 / 最小 / 最大延迟，以及**抖动**（相邻延迟的波动）。
- **延迟曲线**：实时火花图展示最近趋势，失败点一眼可见；下面还有逐条明细。
- **探测间隔可调**：既能高频盯抖动，也能低频长时间守一条链路；也可设固定探测次数。
- **顺手**：ICMP 探测开箱即用，个别环境发不了 ICMP 时会自动引导你改用 TCP ping 测端口级可达；可**同时开多个窗口**并行盯不同目标；也能从抓包记录**带着目标直接开测**。

## 四、DNS 泄漏检测：你的 DNS 真的走隧道了吗

挂了 VPN，流量是走隧道了，但**DNS 查询是不是也跟着走了**？一键看清本机实际在用的**出口 DNS 解析器**：

- 列出**真正在为你解析域名的解析器**：每个的 IP、所在国家、所属运营商。
- 这些解析器**跨了多少个网络**、你的**出口公网 IP** 及其归属；若有，还显示 DNS 查询携带的**客户端子网**信息。
- **只如实列事实、不做红绿判定**，把判断权交给你——因为「算不算泄漏」取决于你的预期：

> 正用着 VPN，却在这里看到**本地运营商**、或**其它国家**的解析器，说明 DNS 查询正在**隧道之外泄漏**。

**完全自包含**：自研检测，不把你导去任何在线检测页，也不依赖任何第三方泄漏检测网站——离线 / 内网环境一样能测。

## 五、什么时候用

- 突然断网，想**一步定位**是哪一环，而不是逐个手动测。
- **抓包 / VPN 停掉后应用集体上不了网**——多半是残留代理，这里一键清掉。
- 连了 Wi-Fi 却打不开网页，怀疑撞上认证门户。
- 盯一条链路的延迟 / 抖动 / 丢包随时间的变化；ICMP 被拦时用 TCP ping 测端口级可达。
- 用 VPN / 代理时，核实 DNS 有没有一起走隧道、本机到底在用谁家的 DNS。
