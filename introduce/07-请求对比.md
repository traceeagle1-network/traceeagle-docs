# 请求对比（Diff）

> 「为什么这次成功、上次失败？」「同样的接口，成功的请求和失败的请求到底差在哪一行？」——把两条请求 / 响应并排一比，答案立刻浮出来。这是排查线上偶发问题、复现差异、验证改动最快的一招。

---

## 一、怎么用：两步搞定

1. 在任意一条流量上右键 **「标记为对比 A」**。
2. 在另一条流量上右键 **「与 A 对比」**。

一个并排对比窗口立刻弹出，逐行标出两条之间的每一处差异。

![流量右键菜单：标记为对比 A、与 A 对比，以及生成代码 / 主机详情 / 重放 / 压测等入口](img/07-context-menu.png)

---

## 二、看什么：请求、响应都能比

窗口顶部可一键切换对比 **请求** 或 **响应**，两侧分别是 A 和 B，各带标签（方法 · 主机 · 状态），一眼知道在比哪两条。对比内容覆盖一条报文的全部：

- **起始行**：请求行（方法 / 地址 / 协议）或响应行（协议 / 状态码）
- **全部请求头 / 响应头**
- **请求体 / 响应体**（自动美化后逐行比对，JSON、XML、表单都好读）

---

## 三、差异一目了然

- **先美化再逐行比**：JSON、XML、表单先自动格式化，再逐行比对——真正变了的字段一眼看到，不被换行 / 缩进等格式噪声干扰。
- **逐行标色**：新增（+）、删除（−）、改动（~）分别高亮，A 侧标红、B 侧标绿，改动行两边并排对照。
- **差异计数**：顶部直接给出「新增 / 删除 / 改动」的行数汇总，规模大小心里有数。
- **完全一致会告诉你**：两条内容相同时明确提示「一致」，不用自己逐行确认；某侧没内容或还未解密，也会**直说**，不让你干等。
- **带行号**：两侧各自行号，定位到具体位置。

![并排对比窗口：顶部切换请求 / 响应，A / B 各带标签与行号，逐行标色，右上角汇总新增 / 删除 / 改动行数](img/07-diff.png)

## 四、真正强大之处：跨会话、跨来源对比

对比的两条记录**不必来自同一个抓包会话**，也不必是同一时间抓的——只要在界面上见过，就能拿来比：

- **成功 vs 失败**：把一条成功的请求和一条失败的并排，立刻看出是哪个头、哪个参数、哪段 body 不一样。
- **手造 vs 真实**：把[请求构造器（Composer）](02-请求构造与重放.md)里**重放 / 发出后抓到**的请求，和历史抓到的真实请求对比，验证「我构造得对不对」「签名算得一不一致」。
- **改动前后**：改了服务端 / 客户端后，把新旧两次请求一比，确认改动是否生效、有没有副作用。
- **跨环境**：测试环境和线上环境同一接口的返回并排看，快速定位配置或数据差异。

> 这也是它比「单看一条请求」强大得多的地方：差异是在**对照**中暴露的，而不是靠你记忆和肉眼扫。普通工具往往只能在**同一会话内、靠肉眼**逐条比。

---

## 五、典型场景

- 排查偶发失败：成功请求 vs 失败请求，锁定差异字段。
- 联调对齐：客户端实际发出的请求 vs 接口文档 / 期望请求。
- 回归验证：改动前后同一请求 / 响应的差异确认。
- 签名调试：手动构造的带签名请求 vs 真实请求，核对每一处是否一致。
